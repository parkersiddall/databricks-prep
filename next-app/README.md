# next-app

The Next.js application. Standard `create-next-app` packaging, nested one level
down so the repo root stays uncluttered — see
[`../docs/decisions.md`](../docs/decisions.md).

For the **design** behind any of this, read
[`../docs/architecture.md`](../docs/architecture.md). For **how to add a category,
test, or practice exam**, see the root [`../README.md`](../README.md). This file
is the directory map: what lives where, and what belongs where.

## Commands

All npm commands run from this directory.

```bash
npm run dev          # http://localhost:3000
npm run build        # also generates .next/types, which typecheck depends on
npm start            # serve the production build
npm test             # vitest, tests/ only
npm run test:watch
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
```

## What belongs where

| Putting in… | When it… |
| ----------- | -------- |
| `lib/` | is pure — takes plain data, returns plain data. Gets unit tests. |
| `stores/` | needs to persist across reloads. Keep it a thin wrapper; push logic into `lib/`. |
| `hooks/` | needs React state, effects, or a store subscription. |
| `content/` | is authored data, or the code that validates and reads it. |
| `components/ui/` | is a presentational primitive reused across pages. |
| `components/layout/` | is page structure rather than a single widget. |
| `app/` | is a route. Compose from the above; avoid logic here. |

Two rules that keep this honest:

- **`src/` holds only shipping code.** Tests live in `tests/`, mirroring `src/`,
  and import through `@/` rather than relative paths.
- **Imports use the `@/` alias**, not `../../`. `@/lib/grading`, not
  `../../lib/grading`.

## Things that will bite you

These are the app-specific ones; the full list is in
[`../CLAUDE.md`](../CLAUDE.md).

- **`npm run typecheck` fails on a clean checkout** with
  `Cannot find name 'LayoutProps'`. Next generates route types into
  `.next/types/`, so run `npm run build` (or `npm run dev`) first.
- **Pages use generated route types** — `PageProps<"/[category]/[test]">`,
  `LayoutProps<"/">` — and `params` is a **Promise** you must await.
- **Content is validated at module load.** A malformed question file fails the
  build with a `[content]`-prefixed message naming the offending id. Normalize
  the data rather than loosening `content/schema.ts`.
- **Anything reading a persisted store must be gated on `useHydrated`,** or the
  server's HTML will not match the client's.
